# 성능 점검 · 최적화 (11/15)

피드백: 「퍼포먼스 최적화」 (앞선 불만: 후반 전투에서 휴대폰 프레임이 떨어진다).
기기가 없어 **PC 에서 재고, 실제로 비싼 것만** 고쳤다. 판정(전투 계산 결과)은 한 비트도 바꾸지 않았다.

- 재는 곳: PC, 창 720×1280, vsync 끔. 휴대폰은 스크립트가 대략 4~8배 느리다고 보고 읽으면 된다.
- 숫자는 모두 PC 값이다. 다른 에이전트가 같이 돌고 있어 ±5% 쯤 흔들린다.

한 일 (모두 「같은 값을 같은 순서로 계산」 —— 건너뛰는 것은 결과가 정확히 그대로인 경우뿐):
- `mv()` · `_aura_mul()` : 부를 때마다 위세 장수(불멸 · 신화 판은 18명)를 다 훑던 것을, 그 키 · 능력치를 실제로 주는 장수만 추려 둔 목록으로. (전체의 약 30%가 여기였다 —— `eff("spd")` 가 틱마다 부대 수 × 2 번 불린다)
- `_gap()` · `_solve()` · `_blocker()` : 축 배열 · `_extent` 호출을 풀어 쓰기 (식 그대로). `_solve` 는 아무도 밀리지 않은 바퀴 뒤로는 돌지 않는다
- 맞닿음 · 몰림 판정: 가운데끼리 충분히 먼 부대는 틈을 재지 않는다 (틈 ≥ 거리/√2 − 발자국 반폭 · 반깊이 —— 확실히 넘을 때만)
- 이동 속도 · 행동 간격: 서 있는 부대(속도 0 → 0) · 준비가 가득 찬 부대는 재지 않는다
- `has_st` · `live_count` · `_foes_of` · `_shown_st` : 람다(any · filter · map) 대신 그냥 훑기. 선호 대열(zone) · 원거리 여부는 부대마다 한 번
- `eff()` : 쓰지 않는 조회 건너뛰기

확인: tests/sim_hash 전체 해시 368176436 · fingerprint 279448047 (턴) / 3295989100 (--rt) · determinism 30판 실패 0 · 새로 만든 tests/sim_perf 의 두 해시(같은 등급 4277092238 · 섞은 판 2186207133 —— 결과 사전 전체) 모두 **고치기 전과 같다**. game.tscn 두 판의 출력도 글자 그대로 같다.

## 3. 남은 것 —— 실제 기기에서 볼 것

1. **전투 시작 멈춤** : 계산이 아직 한 판 0.4~0.8초(PC)다. 휴대폰이면 몇 초 화면이 멈출 것으로 본다 (추정 —— 기기에서 재야 한다). 다음 수는 ① 작업 스레드에서 계산하고 그동안 「출진」 연출 ② 전투 탭에 들어올 때 미리 계산. 스레드는 Battle 의 static 변수(tr_mul · side_trait)를 건드려 이번엔 손대지 않았다. 계산 자체는 아직 사건 기록(L —— 사건마다 18부대 상태를 통째로 적는다, 대략 15%)과 `phys_hit` 의 특기 조회(mv 40~60번)가 크다
2. **초상을 압축 텍스처(ASTC)로** : 지금은 임포트가 무손실 · 밉맵 없음이고 실행 중에 RGBA + 밉맵을 만든다. ASTC 로 내보내면 메모리가 다시 1/4 쯤 되지만 새 일러스트의 화질을 기기에서 눈으로 봐야 하고, 그려진 영역 · 얼굴 자리를 미리 계산해 두는 일이 따른다. 기기 없이 하지 않았다
3. **원본 초상이 쌓인다** : 큰 칸에서 본 원본(한 장 2.8MB)은 판이 끝날 때까지 캐시에 남는다. 오래 하면 다시 는다 (버리려면 그 그림을 쓰는 칸을 다시 그려야 한다). 띠(긴급 · 사망) · 카드 상세는 처음 볼 때 원본 한 장을 그 자리에서 읽는다 (PC 에서 수 ms —— 따로 재지는 않았다)
4. **정적 메모리 220~270MB 의 정체** : 재지 못했다 (글꼴 글리프 · 소리 · 데이터 · 3D 메시일 것). 기기 프로파일러로
5. **전투 HUD 그리기 호출 약 270** : 메달마다 그림이 달라 묶이지 않는다. 메달을 아틀라스 한 장에 굽고 층별(그림 → 띠 → 글자)로 그리면 크게 준다. 병력 띠의 둥근 상자(한 번 21µs) · 적 갑옷 표지도 구울 수 있다. 겹칠 때 그리는 순서가 달라져 이번엔 하지 않았다
6. **탭 페이지 짓기** : 징집 탭 9.7ms 가운데 추천 조합 계산이 6.9ms (`_forge_goals` 3.3 + `bond_goals`). 판 상태가 같으면 다시 계산하지 않게 할 수 있다 (game_screen · run 은 다른 작업과 겹쳐 손대지 않았다). 작은 변화에도 페이지를 통째로 다시 짓는 구조는 그대로다
7. **타일 한 장 그리기 80~150µs** : 둥근 상자 21µs × 1~4 · 원 9µs × 3 · 초상 15µs. 원 · 상자를 그림으로 구우면 줄지만 가장자리가 조금 달라진다. CardTile 의 `DB.trait_list` (34µs, 캐시 없음)도 남았다
8. 전투의 타입2 병사 · 연출 · 바닥 스크립트(0.33 + 0.39 + 0.21ms)는 그대로
9. 타입2 에서도 3D 전장 노드(지형 메시 · 나무 · 병사 메시)는 만들어진다. 시작 시간 · 정적 메모리에 영향이 있을 수 있다
10. 휴대폰의 실제 fps · 부하 조절 단계는 설정의 「성능 표시」 로 확인
