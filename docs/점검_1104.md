## 2. 이번 점검에서 찾아서 고친 것

1. **[높음] 불멸 · 신화 완성 연출이 닫히지 않아 화면 입력이 영구히 막힘** (제가 11/3 에 만든 `forge_fanfare.gd` 실수) —— 자동으로도, 눌러도 안 닫혔다. 고침, 6초 뒤 화면 확인.
2. **[높음] 온라인 방에서 '3일차 진입 시 경고 4회 멸망'(11/3 추가)이 처리되지 않음** —— 점검 모드(test)도 멸망하고, 일반 방에서는 멸망한 사람이 탈락 처리되지 않은 채 남았다(`net/room.gd _advance`). 고침, 점검 모드가 다시 토너먼트까지 감.
3. **[중간] 전투 중 화풍을 2D(점묘 · 타입2)로 바꾸면 병사가 멈춘 채 흰색으로 보임** —— GPU 병사로 시작한 전투는 끝날 때까지 3D, 2D 는 다음 전투부터.
4. **[중간] 쓰러지는 병사가 1~3칸 옆에서 나타남** —— CPU 의 시신 자리 계산을 셰이더 식(늦게 따라오기 · 압축 · 앞줄 오프셋)에 맞춤 (`Squad.gpu_pos`).
5. **[중간] 열이 들쭉날쭉해지면 대열 깊이 계산이 틀어짐** —— 실제로 가장 깊은 칸으로 줄 수를 센다 (`_recount_rows`).
6. **[낮음] 전멸 순간 프레임 끊김(병사 수 제곱)** —— 전멸은 한 번에 쓰러뜨린다.
7. **[낮음] 이미 다 넘어진 시신을 계산으로만 날림** · 다시 시작할 때 이전 부대 참조가 남음 · 배급 후보가 비면 0 나누기 · GPU 칸 번호 1024 한계(병사 수 900 상한).
8. **[낮음] 화면 밖 이름표 장식에서 '다각형 분할 실패' 오류가 쏟아짐** —— 카메라 바로 옆 · 뒤 좌표(수만 단위)는 그리지 않는다. 가까운 카메라에서도 0건.
9. **부대끼리 막 겹쳐지던 것** (사용자 지적) —— 이웃 부대가 대열 안으로 들어오면 그쪽 축으로 대열을 압축(`War3D._squeeze`). 맞붙은 적과는 앞줄이 조금 섞이게.

## 3. 게임 컨디션 · 재미 —— 문제점과 보완 제안 (우선순위 순)

### ① 대전(PvP)이 긴장감이 없다 —— 거의 늘 이긴다 ⚠ 가장 큼
- 자동 진행(사람보다 약한 단순 규칙)조차 대전 성적이 13승 4패 · 17승 0패 · 20승 2패 식이다. 2일차 저녁 순위표: 나 279 PV, 봇 163~185 PV.
- 원인: 봇 성장은 페이즈마다 고정량(`_bot_pv_gain` 22 + 일차×4)이라 내 덱빌딩 속도와 상관없다. 11/3 에 내 수입을 75% 로 줄였어도 봇이 더 약하다.
- 결과: 재미의 긴장은 토벌(경고 4회 멸망)에서만 나고, 대전은 '보상 받는 절차'가 된다.
- 제안: 봇 PV 를 '내 PV 를 따라오는 곡선'(예: 내 PV × 0.85~1.15, 봇마다 성향)으로 바꾸거나, 대전 상대를 같은 순위대에서 고른다. 지면 기본패가 줄어드는 것(현재 승 5 · 패 3)보다 '순위 · 토너먼트 시드'에 걸리게 하면 대전의 무게가 생긴다.

### ② 한 판이 길고 단조롭다 (로컬 테스트 기준)
- 21페이즈 × (징집 → 선택권 → 조합 → 편성 → 토벌 약 17초(2배속) → 대전 약 35초) ≈ 45~60분. 페이즈마다 할 일이 거의 같다.
- 제안 (로컬 테스트용, 실제 '하루 3번' 운영과 별개):
  - **빠른 판 모드**: 4일 12페이즈(또는 페이즈당 보급 2배)로 20분 안에 신화까지 가 보는 설정. 밸런스 확인 · 재미 확인이 빨라진다.
  - **페이즈 사건**: 3페이즈에 한 번 고르는 이벤트(상인 · 귀순 장수 · 역병 · 결투 신청 등 3택1) —— 같은 반복을 깬다.
  - **토벌 보스 기믹**: 지금 토벌은 PV 만 다른 같은 싸움. 일차마다 '화공 무효' · '기병 강함' 같은 조건을 보여 주면 편성을 바꿀 이유가 생긴다(덱빌딩 중심 원칙과 맞음).

### ③ 경제 · 신화 시점 (11/3 조정 뒤)
- 수입을 약 75% 로 줄였다(기본패 환산 누적 142 → 108 · 주 합계 2244 → 1676). 자동 진행 기준 신화는 5~6일차, 3-2 · 5-3 ~ 6-x 토벌이 벽.
- 사람은 자동 진행보다 훨씬 잘하므로 실제 체감은 직접 해 봐야 한다. 너무 빡빡하면 `DB.ECON_ON = false` 로 예전.
- 남은 문제: 유니크 3택1 이 1일차 아침에 와서, 다 몰아 넣으면 수요일쯤 신화가 가능하다. 의도와 다르면 첫 유니크를 2일차 아침으로 미루는 것을 검토.

### ④ 첫 경험(온보딩)이 없다
- 1일차 오전 첫 화면: "장수가 아직 없다. 기본 병종을 조합하거나 선택권으로." 한 줄뿐. 처음 하는 사람은 징집 → 조합(기본 4장 = 고급) → 편성 → 토벌 순서를 모른다.
- 제안: 1일차 오전만 '다음 할 일' 화살표 · 강조(징집 타일 깜빡 → 조합 탭 빨간 점 → 편성 자동 편성 버튼 → 전투 탭). 이미 탭 빨간 점이 있으니 그 위에 한 줄 안내만 얹으면 된다.

### ⑤ 전투 화면
- 좋아진 것: 병사 5,000명 GPU · 군중 대열 · 앞줄 전사와 뒤 병사 메우기 · 공격/피격 동작 · 에이스 무쌍(프리즈 · 흔들림 · 날리기) · 비네트 · 진형 떠밀기 · 겹침 방지.
- 남은 것:
  - **시신이 쌓여 갈색 덩어리**: 5,000명이라 후반엔 땅을 덮는다. 몇 초 뒤 땅에 스며들듯 사라지게(알파 대신 아래로 가라앉기) 제안.
  - **장수(CPU 모델)와 병사(GPU)의 질감 차이**: 장수만 다른 움직임 규칙이라 군중 속에서 튈 수 있다. 장수도 같은 늦게 따라오기 · 꼼지락을 쓰면 자연스럽다.
  - **이름표 18개 + 피해 숫자**가 군중 위에서 여전히 많다. 멀리 볼 때는 '에이스 · 따라가는 부대'만 이름표를 보이는 단계를 하나 더 두는 것을 제안.
  - 타입2(삼국지11) 시안은 2D 라 병사 1,700명 · 64fps. 방향을 정해 주면 다듬는다.

### ⑥ 휴대폰
- GPU 병사는 PC 에서 병목(스크립트)을 없앴지만, 휴대폰 그래픽 칩이 인형 모델 수천 개를 감당할지는 모른다. 릴리스 품질 '낮음' 은 0.4배(약 2,100명). 실기기에서 프레임 · 발열을 보고, 모자라면 휴대폰만 큐브 모양(`War3D.cube_mode`) 또는 0.3배.
- (추정) Vulkan 이 없는 기기에서 Compatibility 렌더러로 떨어지면 MultiMesh 사용자 값이 반정밀도가 되어 GPU 병사 칸 인코딩(×1024)이 깨질 수 있다. 내보내기 설정이 Mobile(Vulkan) 이라 보통은 문제없다.
- 세로 개편 뒤 APK 를 아직 안 만들었다 —— 다음에 실기기로 한 판.

### ⑦ 온라인
- 서버 점검의 가장 큰 메시지가 30KB(10/24) → 53~112KB 로 커졌다. 전투 기록(track)이 길어진 탓으로 보인다. 휴대폰 데이터로 받기엔 크니, 기록을 줄이거나(0.4초 → 0.8초 간격) 압축 확인 필요.
- 서버를 새 코드로 다시 띄워야 클라이언트와 판정이 맞는다(수엄칠군 수정 · 기인 선택권 제외 · 경제 조정).

### ⑧ 코드 · 저장소
- 11/3~11/4 작업량이 크다(경제 · 연출 · GPU 병사 · 타입2 · 점검 장면). **커밋을 권한다** —— 다른 PC 에서 받으면 지금 상태가 하나도 없다.
- `.import` 수백 개 변경은 엔진 재임포트로 생긴 것이라 커밋에서 빼도 된다.
- 쓰지 않는 경로가 쌓였다: KayKit VAT 병사(`vat_enabled=false`) · 그림판 병사(`sprites_enabled=false`) · 실사 나무 · 점묘(숨김) · CPU 병사 경로. 당장 문제는 없지만 GPU 병사가 자리 잡으면 정리 대상.
