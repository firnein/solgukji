# 전쟁 삽화 — 첫 구현

원화 `concepts/battle_painting_01.png`의 방향을 실제 Type2 전투 재생에 적용했다. 엔진·데이터·승패·전투 위치는 그대로다.

## 실행

- 평소처럼 `solgukji_godot/run.bat`으로 게임을 실행한다. 새 기본값은 전쟁 삽화.
- 설정 → 전투 화풍 → 전쟁 삽화 / 기존 군집. 같은 BattleView를 재사용해도 다음 전투에서 전환된다.
- `solgukji_godot/painting_preview.bat`은 화공·궁병·기병·지원 병종이 섞인 실제 엔진 전투를 한 판 재생한다.
- 테스트 장면: `res://tests/formation_preview.tscn -- --painting --mixed --full`. `--baseline`은 기존 군집, 아무 인자 없으면 이전 대표 병사 시안.

## 표현

- 새 4×4 투명 아틀라스: 8병종 × 청/적 2진영. Godot AtlasTexture로 등분하며 원본 이미지를 변형하지 않는다. 축소 시 거칠어지지 않도록 mipmap 사용.
- 보병·궁병은 두 줄, 기병은 쐐기, 지략계는 작은 지휘 집단. 적은 대표 인형으로 각 부대를 표현한다. 병력의 실제 수는 아래 카드와 상단 합계로 유지한다.
- 재생에 기록된 부대 중심·방향을 따른다. 병력 감소는 앞줄의 빈자리와 바닥에 남는 옅은 실루엣으로, 피격은 전열의 짧은 후퇴로, 낮은 사기는 벌어진 간격으로 표현한다. 패주 군기는 기울어진다.
- 얼굴 메달·병력판을 군기와 짧은 장수 이름으로 대체했다. 상세 초상과 병력은 기존 아래 카드에 유지한다.
- 평타·기술의 공중 날리기를 이 화풍에서 생략한다. 기존 광역 입자 대신 작은 먼지·화살 궤적·부대 단위 화염·깨진 방패·둔화 물결·혼란 고리를 그린다.
- 기록에 실제 출처가 있는 확산·화상/수몰 활용은 작은 이동 입자로 연결한다. 출처를 추정하거나 추가 피해를 새로 계산하지 않는다.
- 반복 잔기술 글씨는 숨기고, 큰 타격 숫자는 부대 최대 병력 12% 이상만 1.5초 간격으로 보여준다. 설정의 피해 숫자 '모두'는 원래 숫자 표시를 유지한다. 적 고유기 준비 경고는 한 줄. 인연·고유기 컷인과 군략 공개는 유지한다.
- 전장 바닥에 새 삽화풍 풀·흙 텍스처와 따뜻한 색을 적용하고, 진영 시작선·중앙 경계선은 이 화풍에서 숨긴다. 지형 배치는 기존 화면 규칙을 유지한다.

## 확인과 한계

### 2차 — 고정 사선 시점과 세로 프레이밍

- 기존 탑뷰의 지면 세로 배율 대신 사선 투영과 약한 원근을 적용했다. 가까운 병사·군기는 크고, 먼 부대는 작다. 그림 자체를 세로로 늘리지 않는다.
- 전장 지면의 역투영도 동일한 원근식으로 바꿔 바닥과 병사가 같은 좌표를 따르게 했다. 화살과 연계 입자는 월드 좌표에서 보간한 뒤 투영한다.
- 사용자 추가 피드백에 따라 가로 맞춤에 남던 세로 여백을 별도로 배분한다. 실제 초기 부대의 발자국 모서리를 투영해, 상단 90px와 하단 30px 여백 사이를 사용한다. 병사 확대와 세로 배치는 분리했다. 물리적으로 등방인 카메라가 아닌 모바일 세로 화면을 위한 표현 조정이다.
- 화면 맞춤은 개전 당시 범위를 유지한다. 적이 줄거나 패주해도 생존 부대 중심으로 확대하지 않아 전선의 빈자리가 보인다. 화면 크기가 달라지면 초기 범위를 새 뷰포트에 맞춘다.
- 병사와 군기를 발 위치 기준으로 함께 정렬해, 먼 군기가 가까운 병사 위로 무조건 덮이지 않게 했다. 글자로 된 이름은 읽기 위한 최소 크기를 유지한다.
- 먼 지면의 작은 나무 점무늬는 큰 수목 색 덩어리와 옅은 능선으로 바꿨다.
- 검사 추가: 투영→역투영 왕복 오차 <0.01, 가까운 병사의 원근 배율 >먼 병사, 초기 부대의 좌우·상하 화면 범위, 사용 가능한 세로 영역 활용, 생존 부대가 줄어도 카메라 배율·중심 유지.
- 캡처 파일: `build/painting_oblique_mixed_0.png`, `_8.png`, `_25.png`. 기존 `painting_mixed_*.png`와 비교 가능하다.

- Vulkan 실제 화면으로 540×960 전투를 끝까지 재생했다.
- 같은 편성·시드에서 화풍 켬/끔의 사건 JSON과 양쪽 잔존 병력이 동일함을 검사한다.
- 일시정지 중 대표 대열의 병력 비율이 변하지 않는지, 같은 BattleView에서 기존→삽화 전환 시 중복으로 그리지 않는지 검사한다.
- 결정성 검사 30판 실패 0.
- 400×800 혼합 병종(화공·궁병·기병·지략계) 재생, 일시정지, 기존→삽화 모드 전환 검사 통과. 이미지: `build/painting_mixed_0.png`, `build/painting_mixed_8.png`, `build/painting_mixed_25.png`.
- 원화 그대로 완성된 결과는 아니다. 현재 에셋은 병종당 정지 포즈이며 행군·공격은 위치·흔들림으로 표현한다. 팔다리 동작 프레임과 방향별 그림, 나무·강가의 삽화 표현, 근접 대열 간 시각적 겹침은 후속 개선 대상이다.
- 대표 병사는 실제 개별 충돌 병사를 표시하지 않는다. 실제 부대 중심·진영 위치를 바꾸지 않으며, 새 우회·관통 판정을 만들지 않았다.
- 종료 시 리소스 정리 경고가 기존 캡처 장면에서도 관찰되어, 캡처 성공과 종료 경고를 구분해서 기록한다.

## 2026-11-23 — 대열과 정보 표시 가독성 1차

전장에서 부대 움직임이 먼저 읽히도록 기존 삽화 화면을 조정했다. 전투 엔진·능력치·실제 부대 위치는 변경하지 않았다.

- 초상·이름·병력을 가로 한 줄로 묶고 사기를 그 안의 가는 막대로 유지했다. 초상 반지름 8/10px인 일반 부대의 이름표 전체 높이는 22/26px다. 총대장의 왕관과 금테도 유지한다.
- 이름표의 실제 폭으로 서로 비켜 놓고, 전체 이름표가 전장 안에 들어오도록 제한한다. 긴 이름표의 끝까지 터치로 선택된다.
- 상태 기호 크기 19px와 버프/디버프 색 구분은 유지한다. 평소에는 두 기호와 나머지 개수, 아래 카드를 누른 동안에는 최대 네 칸을 표시한다. 선택이 끝나면 다시 요약한다. 이름표와 다른 상태 줄을 피하며, 아래가 막히면 위쪽 자리도 시도한다. 모든 후보가 막히면 기존처럼 해당 줄을 생략하므로 밀집 교전에서 모든 기호의 상시 표시를 보장하지는 않는다.
- 카드 탭의 기존 2초 강조를 카드 테두리·전장 이름표·대열 바닥에 함께 적용한다. 전투를 다시 시작할 때 강조 기록을 비운다.
- 보병은 가로 6칸·3열, 궁병은 5칸·2열, 기병은 가운데가 앞선 쐐기, 지략계는 3칸·2열의 작은 집단으로 구분한다. 작은 부대는 폭·깊이에 맞춰 더 적게 표시한다. 기병 쐐기의 뒤쪽도 기존 대열 깊이 안에 둔다.
- 대표 병사의 기본 표시 높이를 키우고 최소 높이를 12→14px로 조정했다. 평상시 바닥 면·테두리는 옅게 하고 선택한 대열을 강조한다. 이미지 에셋은 추가하지 않았다.

## 2026-11-23 후속 — 전열 충격·결원 보충·실제 화공 확산

위 표시 배치 조정에 이어 전장 동작을 변경했다.

- 피격 지점에서 가까운 줄부터 뒤쪽 줄로 충격을 전달하고, 병사별 변위·속도와 감쇠로 대열을 회복한다. 부대 중심과 전투 판정 좌표는 움직이지 않으며 병사 발의 접촉 경계도 지킨다.
- 사상자가 생겼을 때 후열의 보이는 줄을 즉시 당기지 않는다. 약 0.32초간 빈자리를 남기고, 후열 병사가 약 0.5초에 걸쳐 한 줄 앞으로 이동한다. 정지 중에는 이 시간도 멈춘다. 피해가 누적되면 간격이 흐트러지고, 실제 패주 상태에서는 서로 다른 간격으로 흩어진다.
- 큰 부대의 대표 대열은 보병 6×5, 기병 5×4, 궁병 6×3, 지략계 3×2로 조정했다. 작은 발자국에서는 열·행 수를 줄인다. 청/적 군기를 병사와 같은 깊이 순서의 GPU 스트림에 추가하고, 낮은 사기와 패주를 기울기로 표현한다. 군기는 셰이더 도형이며 별도 그림 파일은 없다.
- 병사는 공중으로 날리지 않고 전열 안에서 쓰러져 밀린다.
- 실제 `status/burn/spread:true` 사건만 부대 사이의 불길 경로로 표시한다. 경로 출발은 효과 제공자(`contributor`)와 구분한 실제 번짐 출처(`from`)다. 부대 안에서는 불이 들어온 쪽부터 살아 있는 병사의 발 위치로 번지며, 그 자리에 불꽃·연기·그을림을 표시한다. 일반 화상 활용 피해로 확산을 만들어 내지 않는다. 확산 경로는 최대 6개, 1.15초다.
- 전체 재생 검사에서 기존 고유기가 원본 사건에 `_lite`를 써 넣던 문제를 발견했다. 이 표시는 재생 묶음의 `lite`로 옮겨 소리의 강약을 유지하면서 원본 사건을 수정하지 않도록 했다.

검증과 산출물:

- `tests/battle_motion.tscn`: 빈자리 유지·걸어 들어오는 보충, 앞→뒤 충격 전달·감쇠 복귀, 정지·접촉 경계·중심 보존, 실제 엔진 확산 출처, 살아 있는 병사 위의 화염, 확산 예산·추정 경로 금지·초기화·원본 기록 불변 통과. 마지막 verbose 실행에서 리소스 누수 경고 없음.

- 영상 녹화 종료 시 기존 캡처와 같은 리소스 5개 정리 경고가 남았다. 화면/기록 검증 통과와 이 종료 경고를 구분한다.

## 2026-11-23 — 병사 표시 크기 확대

병사가 너무 작다는 화면 피드백에 따라 병사·쓰러진 병사의 표시 크기를 1.4배로 올렸다. 최소 높이는 14→19.6px다. 병사 수·발 위치·대열 간격·이름표는 유지하며 군기에는 확대 계수를 적용하지 않는다. GPU 병사 스트림과 그림자를 그대로 사용한다.

## 2026-11-23 — 전장 병력을 누적 바로 표시

- 전장 이름표의 상시 병력 숫자를 1만 명마다 색이 한 층 쌓이는 바로 바꿨다. 한 층은 천 명 눈금 10칸이다. 3만8천 명이면 3만 층의 바탕색 위에 다음 색이 80% 차며, 피해를 받으면 아래 색이 드러난다. 아군과 적군에 같은 병력 색을 사용하고 진영은 기존 이름표 테두리로 구분한다.
- 만 명 경계 직전의 위층 색과 경계 직후의 아래층 색이 같다. 정확히 0·1만·2만 명인 경우도 처리하며 회복으로 층을 다시 올릴 수 있다. 바는 비율이 아닌 절대 병력에 대응한다.
- 아래 카드 탭이나 따라가기 선택 중인 부대만 `35,312` 같은 정확한 병력을 이름 옆에 표시한다. 선택과 자릿수 변화에 맞춰 이름표가 움직이지 않도록 폭을 고정한다. 높이는 20px를 유지한다. 병력 바는 4px, 사기는 아래 별도 2px 줄이다. 하단 카드와 상단 전체 전황은 유지한다.
- 병력은 기존 화면 병력 감소/회복의 보간을 따라간다. 채운 폭을 화면 픽셀로 양자화해 같은 픽셀 안의 변화에는 다시 그리지 않고, 이름표 폭 측정도 캐시한다. 별도 애니메이션 노드나 타이머를 만들지 않는다.
- `battle_readability`에서 실제 카드 선택, 두 진영의 절대 병력 층, 0/만 단위 경계·피해·회복·색의 연속성, 선택 시 숫자와 이름이 들어가는 폭, 고정 위치, 사기와 상태 줄 부재, 재생 기록 불변·화면 재사용을 확인했다. 테스트 중 표시 경계 값을 주입한 뒤 캡처 전 실제 값을 복원했다.
- 현재 화면: `build/motion5_renderer_troop_layers.png`(실제 전투), `build/battle_troop_layers_selected.png`(실제 카드 선택과 정확한 숫자). GPU 버퍼·그림자·병종 셀 검사 통과, 5초 시점 인형·군기 189개와 반대 진영 발 근접 쌍 0개를 확인했다.
- 실행 검사 중 `rt_battle.gd`의 `_zones.clear()`가 `_sg` 정리 분기 사이에 끼어 들여쓰기 오류를 일으키는 것을 발견해 해당 한 줄을 분기 뒤로 옮겼다. 병력 바 작업에서 전투 공식이나 수치를 수정하지 않았다.
- 짧은 PC 프레임 표본: `build/motion5_profile_troop_layers.json`. 이전 기록과는 별도 표본이며 Android 실측은 아니다.

## 2026-11-24 — 작은 보스 체력 바처럼 포개기

사용자의 정정에 따라 위의 넓은 눈금 바와 전장 숫자 표시를 대체했다. 이름표는 숫자 자리 없이 이름 길이에 맞추며, 보통 두 글자 이름은 32px 폭이다. 3px 두께의 병력 바 뒤에 아래 두 층을 1px씩 비껴 그려 포개진 모양으로 표시한다. 병력과 층이 늘어도 바와 이름표의 전체 크기를 늘리지 않는다. 천 명 눈금은 제거했다.

맨 앞줄이 깎여 없어지면 뒤의 완성된 줄이 드러난다. 정확히 4만 명일 때는 네 번째 줄이 가득 차고, 3만8천 명이면 그 줄이 80%다. 색 한 층은 계속 1만 명이며 아군·적군 기준은 같다. 병력 숫자는 전장에 그리지 않고 선택한 기존 하단 카드에서만 정확한 값으로 보여 준다. 이름표 높이·고정 위치·사기 표시와 카드/부대 연결은 유지한다.

`battle_readability`에서 작은 이름표 폭·숫자 여백 부재·층 경계와 회복·하단 카드의 선택 숫자·위치 고정·원본 기록 불변을 확인했다. 실제 선택 화면은 `build/battle_compact_layers_selected.png`다. 원격의 기술/잔기술 이펙트 변경과 통합한 뒤 전열 동작 및 화공 출처 검사도 통과했다. 전열 검사 종료 시 기존 리소스 3개 정리 경고는 남는다.

## 2026-11-24 — 참고 이미지의 초상·이름·HP·사기 구성

사용자가 제공한 작은 게임 이름표를 기준으로 배치를 바꿨다. 왼쪽에 지름 14px의 장수 초상, 오른쪽 위에 9px 이름, 그 아래에 겹친 HP 바와 가는 파란 사기 바를 둔다. HP의 만 명 단위 층과 선택한 하단 카드의 정확한 숫자는 유지한다. 이름표는 보통 50×20px이며 긴 이름만 필요한 만큼 넓어진다. 병력·등급·선택 때문에 크기를 늘리지 않는다.

초상은 양쪽 모든 부대에 같은 작은 크기로 표시하며 진영은 초상 테두리로 구분한다. 기존 메달의 큰 틀·방향 삼각형은 만들지 않고 얼굴만 캐시한다. 얼굴 굽기는 프레임당 누적 2ms 예산 안에서 나눠 시작하며, 이후에는 구운 이미지를 재사용한다. 이름은 바 위에 테두리 글씨로 표시하고 어두운 패널은 두 바 아래에만 남긴다. 초상도 터치 영역 안에 포함된다. 위치 고정, 버프·디버프 줄 부재, 대열 강조는 유지한다.

`battle_readability`의 양 진영 초상 캐시·고정 프레임 내부 배치·같은 초상 크기·HP 보존과 층 경계/회복·카드 선택·사기·전체 터치 영역·재생 기록 보존 검사를 통과했다. 선택 화면은 `build/battle_profile_hud.png`, 일시정지 표시 없는 실제 재생 화면은 `build/battle_motion_profile_hud/0000.png`다.

짧은 Windows RTX 4080 / Mobile 렌더러 표본은 `build/motion5_profile_profile_hud.json`에 저장했다. 준비 3초 뒤 12초 동안 평균 6.89ms, 95백분위 9.51ms, 최대 17.11ms, 33ms 초과 0회다. 기술 이펙트 통합 이후의 별도 표본이며 이전 표본과 직접 전후 비교하지 않는다. Android 실기기 성능은 미확인이다.

## 2026-11-24 — HP 바의 진영 색 구분

아군 HP는 청색, 적군 HP는 적색 계열로 고쳤다. 겹친 층의 차이는 각 진영 색 안에서 밝기와 채도로 표현하며 층이 바뀌어도 다른 진영 색으로 바뀌지 않는다. 사기는 양쪽 모두 별도 금색 계열로 구분한다. 초상·이름·두 바의 크기와 위치는 유지한다.

`battle_readability`에서 1~32층의 아군/적군 색 구분, 인접 층 구분, 사기와의 구분, 실제 부대 진영이 이름표까지 전달되는 것을 검사했다. 기존 선택·고정 위치·층 경계/회복·기록 보존 검사도 통과했다. 실제 전투 캡처는 `build/battle_motion_camp_hp/0000.png`다.

## 2026-11-24 — 현재/최대 병력과 절대 병력 눈금, 메달 제거

이 절의 구현으로 앞의 겹친 층과 작은 초상 구성을 대체했다. 기존 구현은 병력 100인 기본 부대도 1만 명 한 층의 1%만 채워, 전투 시작부터 죽기 직전처럼 보였다. 이제 채워진 길이는 `현재 병력 / 최대 병력`이다. 100/100과 50,000/50,000 모두 가득 차며, 피해·회복은 같은 비율을 따른다.

HP 바는 모든 부대가 40×5px로 같다. 최대 병력이 클수록 같은 폭 안에 절대 병력 눈금이 촘촘해진다. 솔국지의 눈금은 100명·1,000명·10,000명이며 큰 단위일수록 길고 진하다. 같은 화면 픽셀에 여러 눈금이 들어가면 큰 단위 하나만 그려, 중복 선으로 바 전체가 검어지는 것을 막는다. 눈금은 최대 병력과 표시 배율별로 캐시하며 생성 비용도 바의 실제 픽셀 폭으로 제한한다. 아군 청색·적군 적색, 별도 금색 사기를 유지한다.

전장 초상·메달과 얼굴 이미지 굽기를 제거했다. 이름은 바 위에 가운데 정렬하며 병력 변화나 선택으로 이름표를 옮기지 않는다. 하단 장수 카드는 그대로 선택할 수 있고 정확한 병력도 하단에서 확인한다. 참고한 방향은 LoL의 고정 크기 HP 표시다. [Riot의 렌더링 설명](https://www.riotgames.com/en/news/trip-down-lol-graphics-pipeline)은 HP 표시를 별도 그리기 단계로 다룬다. 위 눈금 단위와 픽셀 중복 처리 방식은 솔국지의 구현이며 Riot 내부 공식을 재현했다고 주장하지 않는다.

`battle_readability`의 기본 카드 편성/장수 편성에서 실제 현재·최대 병력, 피해와 회복, 같은 바 폭, 화면 배율별 눈금과 비용 상한, 진영 색, 메달 부재, 하단 선택, 화면 재사용, 원본 기록 불변 검사를 통과했다. 실제 기본 부대의 시작 화면은 `build/battle_motion_hp_grid_starter/0000.png`다. 테스트용 피해·회복을 주입하는 별도 진단 화면은 `build/battle_hp_grid_starter.png`, `build/battle_hp_grid_heroes.png`다.

## 2026-11-24 — 생략된 고유기 발동 알림

간략 고유기는 아군 왼쪽·적군 오른쪽의 인연 보조 장수 표시 영역에 작은 알림으로 장수명과 기술명을 보여 준다. 인연 보조 장수의 간략 고유기도 포함한다. 양쪽에 하나씩 표시하며 같은 진영의 연속 발동은 순서대로 보여 준다. 알림은 HUD 시간으로 1.5초 동안 유지하고, 큰 컷인 중에는 가려진 알림의 수명을 보존한다. 큐는 진영당 16개로 제한한다. 기 모으기·인연 합류 표시 및 적 고유기 준비 문구와 겹치지 않도록 배치한다.

알림 때문에 전투 시계·배속·슬로우·정지·카메라 값을 바꾸지 않는다. 새 연출용 타이머나 이미지 생성 없이 기존 HUD 갱신에서 그린다. `battle_motion`에서 실제 일반/인연 고유기 기록을 사용해 좌우 구분, 위 시간·카메라 값 보존, 실시간 만료, 큐 상한과 재사용 초기화를 확인했다. 실제 두 진영 발동 화면은 `build/battle_motion_ult_notices/0000.png`다. 캡처 도중 원본 전투 기록의 해시도 유지됐다.

카메라 회전은 아직 적용하지 않았다. 비교할 방향은 전선 전체를 유지한 약한 사선의 고정 구도다. 현재 전장은 2D 삽화 스프라이트와 좌표 투영으로 구성돼 있어, 큰 회전은 병사 그림 방향과 원근을 함께 검토해야 한다. 전투 중 자동 회전을 넣기 전에 고정 각도별 전선·부대 식별을 비교하는 편이 적절하다.

최종 코드의 별도 Windows RTX 4080 / Mobile 렌더러 표본은 `build/motion5_profile_hp_grid_notices.json`이다. 준비 3초 뒤 12초 동안 평균 5.61ms, 95백분위 8.26ms, 최대 11.50ms, 33ms 초과 0회였다. 400×860 창의 짧은 PC 표본이며 이전 기록과의 전후 비교나 Android 실기기 검증은 아니다.
