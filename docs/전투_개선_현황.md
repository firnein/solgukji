# 전투 개선 현황

기준: 2026-11-17, `origin/main`의 `b3bfb39`에서 `fix/battle-motion5` 생성.

## motion.5 APK 기준 확인

사용자가 올린 `origin/motion-5`의 **`d6b983d`**를 확보해 작업 브랜치에 병합했다. 원거리 최근접/범위 수정(`2068be4`)을 유지했다. `main`은 `b3bfb39` 그대로다.

복원 소스의 기준은 Android **1.0z-motion.5 / versionCode 31**의 `solgukji-motion-preview.apk`다. 원 브랜치는 APK의 GDScript 55개를 기준 커밋과 대조해 변경된 5개 스크립트를 복원했다고 기록한다. `97b7964`가 대열 스크립트, `0987270`이 판정·재생 이벤트 복원, `d6b983d`가 설명 문서다. APK 토큰/줄 위치를 Godot 4.6.3으로 비교했다는 기록은 원 브랜치의 검증이며, 이번 작업에서는 배포 기준 **Godot 4.4.1**로 통합 소스와 재생을 직접 확인했다.

- 삽화 병사와 군기, 병종별 대표 대열, 피격 움찔과 병력 감소 빈자리, 패주 표시.
- 원근을 둔 고정 사선 투영, 세로 뷰포트 프레이밍, 지면 역투영, 화살·연계 입자 투영.
- 기존 군집/전쟁 삽화 전환, 일시정지, 사건 재생 검증. 과거 결정성 30판 통과 기록.
- motion.5: `painted_formation.gd`의 병사별 보폭·앞줄 접촉·후열 보충·손실/복구, `war_painting.gd`의 보행 메시·타격 반동·제한된 낙하·화살 재생을 복원했다.
- motion.5: 돌격/창벽, 무쌍, 한실부흥, 불바다 이벤트 데이터와 재생 연결, 작은 장수 메달·이름·진영 표시를 복원했다. 원 브랜치의 252명 표시는 특정 9대9 점검 사례이며 모든 편성의 상한으로 간주하지 않는다.

## 검증 원칙

사거리 판정은 기존 대열 발자국 사이의 간격을 유지하고, 그 안에서 중심 거리가 가장 가까운 생존·비은신 적을 고른다. 고유기는 판정 수치를 바꾸지 않고, 그 수치와 동일한 월드 도형을 표시한다. 예고는 준비 시점의 위치 기준이며 실제 발동 시 적이 움직이면 결과가 달라질 수 있다. 범위에 발자국 일부가 닿으면 중심이 원 밖이어도 맞을 수 있다.

성능은 같은 편성/시드로 재생하고 측정 플랫폼·화면 크기·품질을 기록한다. 실기기를 연결할 수 있게 되면 모델·OS·발열 조건과 프레임 시간 p50/p95/p99, 33.3ms 초과 비율, 교전/고유기 구간을 함께 측정한다. 사용자가 Android 연결 불가를 확인했으므로 이번에는 실기기 측정을 요구하거나 완료했다고 기록하지 않는다.

## motion.5 통합 후 PC 진단

실기기 측정이 아니다. 재현 장면은 `tests/motion5_replay.tscn`, 시드 5100의 같은 9대9 편성, 품질 중간, 카메라 연출 끔, 재생 1배속이다. Windows / RTX 4080 / Godot 4.4.1 Forward+에서 물리 창 400×800(논리 화면 크기는 JSON 참고), VSync 끔·FPS 제한 없음, 준비 3초 뒤 15초를 순차 측정한다. 다른 성능 측정 프로세스를 동시에 실행하지 않는다.

삽화 레이어 숨김은 그 레이어의 갱신과 그리기를 함께 끄는 분리 실험이며, motion.5 이전 버전이나 실제 게임 품질 옵션이 아니다. 다른 엔진/전투/HUD 작업은 남는다. 두 실행의 구간별 프레임 수는 달라질 수 있고, 행군 구간 표본은 특히 작아 단일 수치로 비교하지 않는다. 그리기 호출 수는 화면 전체 값이다.

```powershell
& tools/Godot_v4.4.1-stable_win64_console.exe --path solgukji_godot --resolution 400x800 res://tests/motion5_replay.tscn -- --secs=15 --skip=3
& tools/Godot_v4.4.1-stable_win64_console.exe --path solgukji_godot --resolution 400x800 res://tests/motion5_replay.tscn -- --secs=15 --skip=3 --hide-painting
```

수치 원본은 `docs/benchmarks/motion5_pc_full.json`, `motion5_pc_hidden.json`에 보관한다. 로컬 로그는 `build/motion5_*.log`다. 계측 장면 종료 시 Texture/RID 및 리소스 정리 경고가 발생하므로 기능 검사 통과와 구분한다.

이번 9대9 편성의 초기 표시 정원은 **296명**이다. 아래는 최종 순차 실행 한 쌍의 결과이며 평균은 짧은 단발 실행의 참고치다.

| 조건 | 평균 프레임 | p50 | p95 | p99 | 최대 | 33.3ms 초과 | 평균 그리기 호출 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 복원한 삽화 전체 | 16.17ms | 14.54ms | 19.82ms | 23.23ms | 866.29ms | 0.32% | 1,454 |
| 삽화 레이어 숨김 | 2.31ms | 2.11ms | 4.38ms | 5.79ms | 13.07ms | 0% | 287 |

첫 탐색 실행에서는 전체 13.56ms / 숨김 2.26ms였고, 최종 실행에는 전체 표시 중 866ms의 긴 프레임이 포함됐다. 이 값을 버리거나 모바일 지연으로 단정하지 않았다. 단발 실험으로 OS 스케줄링·창 상태·리소스 준비 중 어느 원인인지 분리할 수 없다. 다만 같은 PC에서 삽화 레이어의 갱신/그리기를 제거하면 비용이 크게 줄어 이 경로가 우선 프로파일링 대상임을 확인했다. 최종 고유기 구간 전체 표시 p95는 20.65ms, 교전 구간은 19.69ms였다.

통합 후 재검증: `target_area_regression`(불바다 첫 틱 경계 포함), 결정성 30판, 후열/사기 검사, 혼합 편성 전체 재생이 통과했다. `motion5_replay`의 대열 손실·후열 보충·복구·정지, 화살·돌격·접촉·낙하 이벤트 전달, 개수 제한·초기화도 통과했다. PC Vulkan Mobile 렌더러 기동 및 화면 그리기를 확인했으며, 이는 Android 기기 테스트가 아니다.

## 남은 결함·후속 확인

- Android 실기기 프레임 저하는 미검증이다. PC에서 삽화 레이어 비용을 확인하더라도 모바일 GPU/발열/메모리/프레임 동기화 문제의 원인 확정은 아니다.
- 병사별 그림자·변환·보행 메시·그림과 효과가 다수의 그리기 호출을 만든다. 외형을 보존하는 배치 렌더링과 메시 캐시 준비가 성능 개선 후보지만 이번 복원에 검증되지 않은 렌더러 교체를 섞지 않았다.
- 원거리/기병의 전투 기여와 전설 주유의 평타 역할은 별도 밸런스 과제다. 최근접 규칙 수정이 성능 균형까지 보장하지 않는다.
- 원 브랜치의 후속 과제인 화살의 분산·시간차 낙하, 작은 부대의 접촉·보폭 개선은 남아 있다.
- 전체 온라인 시험의 준비 단계 기대값과 종료 시 리소스 정리 경고는 별도 조사 대상이다.
