레시피는 지금처럼 정확한 재료를 요구하는 고정 결과 구조로 둡니다. 개선의 초점은 두 가지입니다. 페이즈 중에 “다른 목표인지, 거의 같은 목표인지”가 바로 보이게 하고, 같은 등급 안에서 무엇을 만들었는지가 역할로 체감되게 합니다. 수치 변경은 이 문서의 범위가 아닙니다.

요청서의 “고급 근중복 10쌍”은 다른 병종 고급끼리 겹치는 수와 같습니다. 같은 병종끼리 겹치는 23쌍은 그와 별도로 있습니다.

A. 문제 정의

지금 잘 되는 것

  • 모양이 등급마다 하나입니다. “전설은 희귀 둘 + 고급 둘”처럼 등급만 알면 재료의 모양이 읽힙니다.
  • 고급이 세력 4 × 병종 8 격자로 고릅니다. 병종마다 4장이라 특정 병종 고급이 병목이 되지 않습니다.
  • 목표가 갈라집니다. 같은 손패에서 전설·기인·초월 중 어느 쪽을 노릴지 고르는 구조가 이미 있습니다. 원랜디처럼 특정 유닛을 정확히 요구하는 방식이고, 그 자체는 장르의 정상 구조입니다.
  • 장수 개성이 수치 밖에도 있습니다. 잔기술 55종(인물별 연의 일화), 초월·신화의 위세, 기인의 기능이 있습니다.

페이즈 중 판단을 막는 것

  1. 비슷한 고급이 구별되지 않습니다. 같은 병종 고급 둘이 재료 3장을 공유하면, 타일만 봐서는 두 목표가 다른지 알기 어렵습니다. 차이는 재료 한 장인데 그 한 장이 강조되지 않습니다.
  2. 기인과 전설의 갈림길이 갈림길로 보이지 않습니다. 세 쌍은 재료 3장을 공유합니다. 고르는 순간 “무엇을 포기하는지”가 화면에 드러나지 않습니다.
  3. 종착 상태가 말없이 처리됩니다. 디테일창은 다음 단계가 있을 때만 그 칸을 보여 줍니다. 신화로 이어지지 않는 불멸 20장과 초월 23장은 아무 표시가 없습니다. 그래서 “완성형”인지 “아직 갈 곳이 있는지”를 빈칸에서 추론해야 합니다.
  4. 같은 등급 결과의 차이가 타일에 안 보입니다. 조합 타일에는 초상, 이름, 모자란 수만 있습니다. 잔기술·위세·기능처럼 역할을 가르는 정보는 디테일창을 열어야 보입니다.
  5. 기본패 수요가 병종마다 다릅니다. 레시피에 직접 드는 기본패는 기병 46, 술사 27입니다. 징집은 8종 균등이라 기병 기본패가 상대적으로 모자라게 느껴질 수 있습니다. 실제 체감은 플레이 기록으로 확인이 필요합니다.
  6. 기인 안내 문구가 모호합니다. 디테일창은 “한 판에 1장만 만들 수 있고”라고 적습니다. 실제 규칙은 같은 기인을 한 판에 한 장이고, 서로 다른 기인은 여러 장 가질 수 있습니다.

B. 개선 원칙

  1. 판단은 타일에서 끝난다. 페이즈 시간 안에 시트를 여러 번 여닫을 여유가 없습니다.
  2. 다른 목표는 다르게 보인다. 비슷한 레시피는 공통 재료보다 다른 재료 한 장을 앞세워야 혼동이 줄어듭니다.
  3. 모양은 다양하되 재료는 5장 이하로 둔다. 11/5 결정으로 희귀는 비용마다 모양이 다르고, 능력치가 비용을 따라갑니다. 다만 재료가 5장을 넘거나 자원 축이 늘면 판독 부담이 커집니다.
  4. 같은 등급은 수치가 아니라 역할로 가른다. 잔기술·위세·기능은 이미 있는 데이터라 한 단어로 보여 주기만 하면 됩니다.
  5. 종착은 상태로 표시한다. 최종형이라는 사실을 명시하면, 빈칸에서 추론하던 판단 하나가 줄어듭니다.
  6. 생성 규칙은 검사로 지킨다. 레시피는 생성기가 다시 만들기 때문에, 규칙이 테스트에 없으면 다음 재생성 때 되돌아옵니다.

C. 개선안

우선순위 순서입니다. 범주: ① 가독성 · 중복 완화 ② 목표 가시성 ③ 같은 등급 차별화 ④ 생성 가드레일.

C-1. 종착 · 분기 상태 배지

대상
UI · 정보 구조 (game_screen.gd 조합 타일 · 레시피 시트 · 디테일창)
현재 증상
디테일창의 “다음 단계” 칸은 갈 곳이 있을 때만 나옵니다. 신화로 이어지지 않는 불멸 20장, 초월 23장은 표시가 없습니다.
제안
불멸 · 초월 · 기인 · 신화에 상태 배지를 하나씩 붙입니다. 불멸은 완성형 또는 신화 분기, 초월은 완성형 · 위세, 기인은 기능 · 같은 기인 1장, 신화는 판당 1장입니다. 신화 분기형 불멸은 배지 옆에 이어지는 신화 이름과 필요한 유니크를 적습니다.
모바일 효과
“이 불멸에서 멈춰도 되는가”를 빈칸이 아니라 배지로 바로 압니다.
리스크
‘완성형’이 ‘막다른 길’로 읽히지 않게 문구를 고릅니다. 배지가 늘어 타일이 복잡해지지 않도록 등급 테 근처 한 자리에만 둡니다.
검증
불멸 31장 전수: 배지가 신화 재료 여부와 정확히 일치하는지 자동 점검. 360×800 화면에서 타일 겹침 확인.

C-2. 비슷한 레시피는 ‘다른 재료’를 앞세운다

대상
UI (조합 타일 · 레시피 시트)
현재 증상
고급 33쌍, 기인↔전설 3쌍이 재료 3/4를 공유합니다. 시트는 재료를 같은 무게로 나열합니다.
제안
고급 타일 귀퉁이에 제 병종을 뺀 두 기본패 병종 아이콘을 작게 둡니다. 고급끼리는 이 두 아이콘이 곧 차이입니다. 레시피 시트에서는 같은 등급의 비슷한 레시피와 다른 재료를 강조색으로 표시하고, 아래에 “비슷한 조합: ○○ (다른 재료 1장)”을 한 줄로 적습니다.
모바일 효과
두 목표가 같은 재료 셋을 두고 경쟁할 때, 마지막 한 장이 무엇인지 한눈에 봅니다.
리스크
아이콘이 작으면 오히려 소음이 됩니다. 고급과 갈림길 쌍에만 적용하고 상위 등급 타일에는 넣지 않습니다.
검증
근중복 쌍 목록을 기준으로 시트마다 강조 재료가 정확히 1장인지 확인. 고급 32장 타일 스크린샷 비교.

C-3. 같은 병종 고급 근중복을 구조적 최소로

대상
생성 로직 (lines.py의 고급 짝 T3 자동 배정)
현재 증상
같은 병종 고급끼리 23쌍이 3/4를 공유합니다. 병종별로 기병 5 · 도적 4 · 유생 4 · 모사 3 · 창병 2 · 궁병 2 · 책사 2 · 술사 1쌍입니다.
제안
고급은 “제 병종 2 + 다른 병종 2”라서, 같은 병종 4장이 남은 7개 병종에서 짝을 고릅니다. 겹치지 않는 짝은 셋까지만 가능하므로 병종마다 1쌍, 전체 8쌍이 최소입니다. 짝 배정 규칙을 “같은 병종 안에서 다른 병종 짝끼리 겹치는 병종은 최대 하나, 겹치는 쌍은 병종마다 하나”로 바꾸면 23쌍을 8쌍으로 줄일 수 있습니다. 재료 수 · 등급 · 비용은 그대로입니다.
모바일 효과
같은 병종 고급 넷 중 셋은 재료만 봐도 서로 다릅니다.
리스크
다른 병종끼리 겹침(현재 10쌍)이 늘어날 수 있습니다. 바뀐 고급은 희귀 · 전설 레시피에서 재료로 쓰는 쪽도 다시 확인해야 합니다. 플레이어가 외운 고급 레시피가 바뀝니다.
검증
recipe_check 0 · 0 · 0 유지, 같은 병종 근중복 = 8, 다른 병종 근중복 ≤ 10, 같은 등급 동일 레시피 0.

C-4. 기인 ↔ 전설 갈림길을 ‘선택’으로 보이게

대상
UI 우선, 필요하면 생성 로직 (lines.py KIIN의 인연 표)
현재 증상
세 쌍이 같은 병종 전설과 재료 3장을 공유합니다. 주환↔여몽은 엄백호·능통·장흠, 방통↔제갈량은 마량·저수·이적, 미축↔유비는 비의·장완·간옹입니다.
제안
갈림길이 의도라면 데이터는 두고, 두 레시피 시트에 서로를 “갈림길”로 표시합니다. “같은 재료 3장 · 한쪽만 만들 수 있음 · 다른 재료 1장”과 각자의 역할 한 줄을 함께 적습니다. 의도가 아니라면 기인 쪽 인연 재료 하나를 같은 세력의 다른 희귀로 바꿔 공유를 2/4로 낮춥니다.
모바일 효과
“무엇을 포기하는가”가 고르는 순간에 보여, 갈림길이 실수가 아니라 선택이 됩니다.
리스크
데이터를 바꾸면 인연(연의 관계)의 맛이 줄 수 있습니다. 그래서 확인 질문 2번을 먼저 정합니다.
검증
기인 22장 × 같은 병종 전설 전수: 공유 3/4 이상은 갈림길 허용 목록에 있는 것만.

C-5. 타일에 역할 한 단어

대상
UI (조합 타일 · 추천 목표 · 보유 패)
현재 증상
같은 등급 결과는 초상과 이름으로만 구분됩니다. 잔기술 55종, 위세, 기인 기능은 디테일창 안에 있습니다.
제안
전설 이상 타일 아래에 역할 한 단어를 둡니다. 신화 · 초월은 위세 이름, 기인은 기능(부활 · 고유기 끊기 …), 전설 · 불멸은 잔기술 이름(합비 돌격 · 괄골요독 …)입니다. 새 데이터는 필요 없습니다.

“전설 하나 더”가 아니라 “합비 돌격을 쓰는 장료”로 읽혀, 무엇을 만드는지가 바로 체감됩니다.
리스크
글자 수 제한이 필요합니다(4~5자). 긴 이름은 줄임표 대신 짧은 별칭을 데이터에 둡니다.
검증
역할 단어가 빈 카드 0장, 6자 초과 0장 자동 점검. 작은 타일(86×112)에서 잘림 확인.

제안

검증
자동 진행 판의 일차별 추천 기록에서 이유 칩이 비지 않는지 확인.

C-7. 기본패 수요 편차는 먼저 관찰한다

대상
정보 구조 · 플레이 기록 분석 (PlayLog · analyze_playlog.py)
현재 증상
레시피에 직접 드는 기본패는 기병 46 · 유생 38 · 책사 37 · 모사 37 · 창병 36 · 도적 34 · 궁병 34 · 술사 27입니다. 징집은 8종 균등입니다.
제안
수치를 바로 바꾸지 않습니다. 플레이 기록에 “조합이 기본패 병종 하나 때문에 막힌 횟수”를 남겨 실제 병목인지 봅니다. 병목이 확인되면 그때 고급 짝 배정(C-3)에서 기병 기본패를 덜 쓰는 쪽을 검토합니다. 화면에서는 갈무리한 목표에 필요한 기본패 병종을 징집 화면에 작게 표시할 수 있습니다.
모바일 효과
“기병 기본패가 왜 늘 모자라지”라는 막연한 느낌이, 무엇을 모아야 하는지로 바뀝니다.
리스크
징집 확률 조정은 밸런스 영역이라 이 안에서 다루지 않습니다.

C-8. recipe_check에 더할 제약 후보

대상
검증 테스트 (tests/recipe_check.gd) · 생성기 (lines.py)
현재 증상
지금 검사는 잘못된 조합 · 얻을 길 없는 카드 · 순환만 봅니다. 근중복과 갈림길은 재생성 때마다 달라질 수 있습니다.
제안
  • 등급별 슬롯 수가 하나인지 (고급·희귀·전설·기인·신화 4, 초월 3, 불멸 5)
  • 같은 등급 안 동일 레시피 0
  • 같은 병종 고급 근중복 ≤ 병종마다 1
  • 기인 ↔ 같은 병종 전설 공유 3/4 이상은 허용 목록에 있을 때만
  • 신화 재료가 되는 불멸 목록이 신화 명단(MYTH12)과 1:1
  • 재료에 은퇴 · 적 전용 카드 0
  • 전설 이상 카드의 역할 단어(C-5)가 비지 않음
모바일 효과
간접 효과입니다. 화면에서 다듬은 가독성이 다음 재생성 때 무너지지 않습니다.
리스크
제약이 많아지면 생성기가 해를 못 찾을 수 있습니다. 실패 시 위반 목록을 출력하고 멈추게 합니다.
검증
현재 데이터로 돌렸을 때 실패하는 항목이 C-3 · C-4의 대상과 정확히 일치하는지.

C-9. 기인 안내 문구

대상
UI 문구 (디테일창 기인 칸)
현재 증상
“한 판에 1장만 만들 수 있고”라고 적혀, 기인 전체가 한 장뿐인 것처럼 읽힙니다.
제안
“같은 기인은 한 판에 한 장. 다른 기인은 여러 장 둘 수 있다. 다른 조합의 재료로 쓰이지 않는다.”
모바일 효과
기인을 하나 만든 뒤 다른 기인을 노려도 되는지 바로 압니다.
리스크
없음
검증
문구 확인

11/5 결정 사항 — 희귀 조합 다양화

희귀를 “고급 2 + 기본 2” 하나로 두지 않고, 희귀마다 비용을 다르게 정했습니다. 능력치 · 병력 · 전력값은 비용을 따라갑니다. 자기 전설이나 초월로 이어지는 줄기 희귀는 재료 웃돈을 1 붙여, 비싸도 능력치는 그만큼 오르지 않습니다.

비용 (기본패 환산)모양희귀 수
7고급 1 + 기본 34
8고급 1 + 기본 46
9고급 2 + 기본 18
10고급 2 + 기본 28
11고급 2 + 기본 38
12고급 37
13고급 3 + 기본 12
  • 희귀 평균 비용은 9.9로, 예전 10과 같습니다. 전설 28 · 초월 67 · 불멸 95 · 신화 124의 평균 비용도 그대로입니다.
  • 같은 모양 희귀끼리 재료가 한 장만 다른 쌍이 11쌍에서 2쌍으로 줄었습니다.
  • 전설 비용은 재료 희귀에 따라 23~31로 퍼졌습니다. 전설 능력치는 아직 비용을 따라가지 않습니다. 따라가게 할지는 따로 정할 일입니다.

D. 하지 말아야 할 변경

  • PV · 능력치 · 비용 · 드랍률 · 확률 · 피해량을 이 개선의 일부로 바꾸는 것. 필요해 보여도 “검토 필요” 후보로만 둡니다.
  • 등급 사이 격차를 좁히는 것. 예: 상위 등급 재료 수를 줄이거나, 하위 등급 결과를 상위처럼 보이게 하는 것.
  • 재료를 6장 이상으로 늘리는 것. 등급 안 모양 다양화는 11/5에 희귀부터 결정됐고, 재료 5장 이하가 조건입니다.
  • 새 자원 축을 추가하는 것. 군량 같은 재화는 별도 결정 사항이고 이 문서의 범위가 아닙니다.
  • “아무 희귀 3장” 같은 일반 슬롯으로 바꾸는 것. 정확 레시피는 장르의 정상 구조입니다.
  • 숨겨진 명령어 · 암기형 조합 · 조건 분기 레시피를 넣는 것.
  • 초월이 위로 이어지지 않는 것을 결함으로 보고 상위 재료로 쓰게 바꾸는 것. 초월은 의도된 종착입니다.
  • 모든 불멸을 신화로 잇는 것. 불멸은 최종 등급이고, 신화는 11명만의 별도 분기입니다.
  • 고정 결과 레시피를 무작위 결과나 선택형 결과로 바꾸는 것.

E. 실행 전 확인 질문

  1. 1. 고급 레시피 재배정 범위C-3처럼 고급 짝을 다시 배정해 같은 병종 근중복을 23쌍에서 8쌍으로 줄여도 되나요? 플레이어가 외운 고급 레시피 일부가 바뀝니다.
  2. 2. 기인 ↔ 전설 세 쌍의 의도주환↔여몽, 방통↔제갈량, 미축↔유비가 같은 재료 3장을 두고 갈리는 것이 의도된 갈림길인가요? 의도라면 UI 표시만, 아니라면 재료 하나를 바꿉니다.
  3. 3. 불멸 상태 표기 문구신화로 이어지지 않는 불멸을 “완성형”, “최종”, “정점” 중 무엇으로 부를까요? 신화 분기형은 “신화 분기”로 충분한가요?
  4. 4. 타일 역할 단어의 출처전설 · 불멸 타일에 잔기술 이름을 쓸까요, 아니면 짧은 역할 분류(돌파 · 저격 · 회복 …)를 쓸까요? 잔기술 이름은 맛이 있고, 분류는 비교가 쉽습니다.
  5. 5. 기본패 병목 확인 방식C-7을 플레이 기록으로 먼저 확인한 뒤 판단해도 되나요? 아니면 지금 고급 짝 재배정 때 기병 기본패 수요를 함께 낮추길 원하시나요?
